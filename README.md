# Sales daily report

Небольшой скрипт на Python для расчёта ежедневных показателей продаж по артикулам из `sales.csv`.

## Требования

- Python 3.10 или новее
- Сторонние зависимости не нужны

## Запуск

Из корня проекта выполните:

```bash
python main.py
```

Скрипт прочитает `sales.csv` из корня проекта и создаст рядом `daily_by_sku.csv`.

Можно указать другие пути:

```bash
python main.py --input path/to/sales.csv --output path/to/daily_by_sku.csv
```

## Логика расчёта

- `orders` — количество уникальных `order_id` для пары `sku` + `order_date`. В расчёт входят и `delivered`, и `cancelled`.
- `revenue` — сумма `quantity * price` только для заказов со статусом `delivered`.
- Статусы нормализуются: удаляются пробелы по краям и регистр приводится к нижнему. Опечатка `canceled` приводится к `cancelled`.
- Повторяющийся `order_id` учитывается один раз. Если строки с одним `order_id` содержат разные данные, скрипт останавливается с понятной ошибкой, а не выбирает запись произвольно.
- Отсутствующее `quantity` у отменённого заказа не влияет на выручку. Отсутствующее или некорректное количество у выкупленного заказа считается ошибкой, поскольку без него нельзя корректно посчитать выручку.
- Денежные значения обрабатываются через `Decimal`, чтобы избежать ошибок двоичной арифметики с плавающей точкой.
- Итог сортируется по `sku`, затем по `order_date`.

## Что обнаружено в исходной выгрузке

Проверка файла из задания (13 858 строк):

- 60 повторных строк с уже встречавшимся `order_id`; все эти повторы полностью совпадают с исходными строками.
- В столбце `status` есть варианты регистра, 11 значений с пробелом в конце и 3 записи `canceled` вместо `cancelled`.
- В 4 отменённых заказах отсутствует `quantity`. На число заказов это не влияет, а выручка по отменённым заказам всё равно не рассчитывается.
- Пустых значений в остальных обязательных полях и некорректных дат при проверке не обнаружено.

## Как проверял результат

1. Запустил скрипт на исходной выгрузке и проверил, что сформирован CSV с четырьмя требуемыми колонками.
2. Сверил контрольные итоги после удаления повторов: 13 798 уникальных заказов, из них 12 047 `delivered` и 1 751 `cancelled`.
3. Проверил, что сумма `orders` по всем строкам результата равна 13 798, а общая выручка по `delivered` равна 10 276 540 рублей.
4. Запустил автоматические тесты: `python -m unittest discover -s tests -v`. Тесты проверяют учёт отменённых заказов, исключение отменённых из выручки, удаление повторов, нормализацию статусов и обработку конфликтующих `order_id`.

## Ограничения

Скрипт рассчитан на формат CSV из задания и известные варианты статусов. Неизвестный статус, некорректная дата, конфликтующие записи с одним `order_id` или некорректные числовые значения приводят к явной ошибке, чтобы не создавать потенциально неверный отчёт.
